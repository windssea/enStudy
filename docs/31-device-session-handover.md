## 孩子看到的流程

同一台设备刷新，继续原来的题目、选项顺序、提示与已保存回执。换设备或重新取得儿童授权后，先读取只读进度，显示“在这台设备接着学”；点击后才接续。另一台设备随即失去新作答、提示和下一步权限，不会在后台自动抢回来。

只读状态下题目可以阅读，作答区域用原生disabled fieldset停用，接续、刷新、回地图在区域外。地图续学入口会说明需要接续。直接从新设备选择其他任务也不能悄悄暂停原设备的活动任务，须先处理接续。

接续后保留整轮assignment、题目呈现快照、当前位置、提示和回执，换发设备所有权与版本。保存过的同一答案重试仍可读取原回执，但不会产生新的证据、积分或推进；旧设备不能提交未作答的新题或跳题。

页面重新获得焦点、从后台回来时读取最新状态，不设持续轮询。写入遇到会话变化，会停止本页作答并读取进度，失败时留下明确的刷新入口，不自动接续。读取期间若本页开始了更新操作或切换身份，过期响应被丢弃。

同题输入在读取进度时保留；如果另一台设备已经换到新题，把原输入暂存在本页“上一步尚未保存的输入”里，并为新题准备空输入。草稿只在本页内存，刷新或关闭后不保留，界面明确说明；不是离线队列，也未同步到其他设备。恢复历史正确回执不重新播放3D庆祝。

## 权限与并发

- 设备以当前儿童授权grant区分，不采集硬件指纹。同一浏览器共享Cookie的标签页属于同一授权，不能称为每标签页独占。
- `learning_sessions` 增加 `lease_grant_id` 和 `lease_version`。只有匹配当前授权才返回lease；其他设备返回 `leaseId:null` 和 `access:takeover-required`。活动、结束及只读状态均由服务端提供。
- `POST /sessions/:id/takeover` 要求 `clientRequestId` 与 `expectedLeaseVersion`。一个D1 batch原子检查有效grant、父会话、活动状态及旧版本，再更新所有权并写入 `session_claims`。同一请求重试不重复换发；同请求不能换设备、任务或版本。被后续接续取代的旧请求返回409，不能再次夺回。
- 答案、提示、下一步和完成的写入均核验设备归属，且在SQL提交时再次检查lease和有效授权。仅事前读取一次不足以阻止并发接续。
- 新任务创建遵守每个孩子只有一个active会话的现有唯一索引：同事务先暂停本授权的旧活动任务，再受授权及外部活动任务检查创建新任务；失败整批回滚，不能留下半个新任务。两个不同设备同时开题只有一个成功。
- `0011_session_ownership.sql` 已本机应用。迁移前的会话保持未认领，不随意分配给最近登录设备；用户明确接续后保留原题并换发新lease。历史迁移不覆写。

`/sessions/current` 同时返回childId。新前端的学习请求带页面当前 `X-EQ-Child-ID`，服务端与Cookie解析的孩子核对；不匹配返回 `IDENTITY_CHANGED`，阻止旧页面把新任务写到刚切换的孩子名下。该头不是认证凭据，不能靠伪造头访问其他孩子。未发送此头的兼容客户端仍受原有家庭、孩子和设备授权约束。

同源标签页通过BroadcastChannel通知身份变化，只发送变化信号，不发送昵称、答案或凭据；接收端重新读取身份并清理旧草稿、进度和会话，不循环广播。无此API时仍有回到页面后的核对与服务端写入保护。真实浏览器消息时序尚待实测。
