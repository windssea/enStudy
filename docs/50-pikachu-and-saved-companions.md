# v0.29 粘土皮卡丘与档案伙伴

本阶段优先补齐用户明确要求的宝可梦形象，制作皮卡丘模型，并将伙伴选择接入儿童档案、地图与各学习场景。课程仍为192/288课，本次不虚增课数。注册继续关闭，指定管理员密码不变，Cloudflare保持免费和两套既有独立D1。

## 角色与建模

新增从基础几何建立的皮卡丘模型，包含黑色耳尖、红脸颊、闪电形尾巴与两道背纹。角色名参考[Pokémon官方家长页面](https://parents.pokemon.com/en-us/video-games-and-apps/)；皮卡丘是宝可梦角色，本项目制作的是该角色的粘土模型，未将它称作原创角色，也未下载现成模型或官方插画替代建模。

实际使用本机Blender 5.2.1 LTS后台CLI；本会话没有暴露Blender MCP工具。保留可编辑`design-assets/clay-pikachu-v1.blend`、建模源码、导出与重建脚本，以及真实Cycles渲染。

最终GLB为25个网格、22,924三角面、1,107,712字节，带顶点环境遮蔽和PBR材质。主体为高粗糙度粘土，眼睛有轻微珠光；复用棚灯、128尺寸PMREM和受预算限制的软阴影，不下载外部HDR。狐狸GLB及其检查摘要保持不变。

第一轮实渲发现五官边缘裁切，原因是对已经贴合的几何再次按深度贴合。现将建模导出的原始五官与运行时备用形状区分：Blender只贴合一次；网页加载备用形状自行贴合。11个细节投射均命中承载曲面，25个部件经重合缝焊接后全部无开口、非流形边、退化面或非法坐标，体积为正；嘴形在源模型中已有端盖。检查失败会停止导出，不以填洞隐藏错误。

正面、侧面、背面与三分之四视角实际渲染已检查。另从最终GLB经同一运行姿态函数导出挥手和安静状态，再用Blender实渲，核对层级、五官贴合、关节和朝向。单元检查遍历四种反馈的短动作阶段，并检查闲置时双脚不下穿地面；仅主动招呼/回执反馈时短暂轻跃。耳朵和尾巴小幅动作、眨眼沿用暂停策略。QA文件绑定实际GLB的SHA-256。

这些证据覆盖列出的静态网格与姿态，不等于网页GPU、实际触控或所有硬件已经验收。Tabbit仍退出69，PC/iPad实际视觉、缩放、帧率和发热待验。

## 选择与交互

地图下方的“换个伙伴：橙橙 / 皮卡丘”默认收起，摘要显示当前伙伴。展开后用原生fieldset、legend、radio和文字标签选择，图片作为装饰；保存前不把试选当成已保存。选中状态同时有边线、选中圆点和“当前伙伴／待保存”文字，焦点可见，触控区域至少52px、间距12px。窄屏自动换行，课程开始按钮继续是主要操作。

卡片下方有独立3D试选舞台，角色居中放大，不附带无关单词道具。可先挥手和转身看背面，2D与错误降级同样对应试选角色；试选只改变这个预览，不写服务器，也不改变当前全站伙伴。保存成功后才将该选择应用到各学习场景。预览仅在展开且进入视口后加载，关闭时卸载，仍受全站安静与活动暂停控制。

保存后，地图、单词、句式、工坊、课程、复习与反馈场景使用选定伙伴。2D与加载/错误降级也对应同一角色，皮卡丘背面显示背纹与尾巴；文字动作从狐狸的“看看背包”切换为“看看尾巴”。朗读、后台、离屏、安静与系统减少动效沿用原控制。加载新模型时刷新阴影，即使在安静模式也不保留旧角色阴影。

初次展开会读取服务器最新选择并同步当前画面。网络丢失保存回执时只读回真实状态，不盲目覆盖其他设备；切换档案或关闭选择会中止旧请求，迟到回调不能写入另一个孩子或较新版本。保存状态有明确成功/失败反馈，档案失效时提供查看档案的入口。

## 数据、并发与学习边界

新增0030迁移创建独立`child_companions`表，本机已应用两条命令，后续不覆写。通过儿童与家庭的复合外键归属，并随儿童档案删除级联清理。旧档案无记录时使用狐狸、版本0，读取默认值不批量写入历史档案。

`GET/POST /api/v1/learning/companion`需要有效儿童授权；写入同时验证选定档案header与显式body.childId，只使用服务端actor作为数据归属。两种角色枚举、整数版本和请求ID均校验。保存采用版本条件更新和命令ID，响应丢失重试只确认一次；不同设备同版本并发只有一个成功，旧命令不会恢复旧选择。另一台设备先读回当前版本后可明确改选。

选择不写入答题、复习、奖励或学习流版本，不替换题目、设备lease或学习进度。身份读取返回当前档案的companionId和版本；家长凭据、注册策略与AI配置不变。偏好只影响外观，不参与成绩判定。

两种角色为独立指纹资源，按当前角色渲染加载；离线静态包包含两者，继续受每模型1.7MB、总包8MB约束。身份与偏好API不进入公共静态缓存，离线确认协议仍为1。新增公开`companionProtocol:1`能力标记，课程版本未变时线上验收仍可识别新版Functions，避免仅看到新静态文件就误报新接口已上线。

最终静态清单`eq-shell-v1-e1540d61b5c2fba9`包含31个资源、4,124,407字节；两份模型为`clay-fox-v1-D-K4NT2e.glb`和`clay-pikachu-v1-4UudSGsd.glb`。模型选择与试选复用已缓存的几何，各场景独立拥有材质和姿态，关闭预览释放自己的实例。
