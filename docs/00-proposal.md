# 英语学习网站方案评估与建议

建议建设“原创课程为基础、游戏任务为载体、复习引擎负责巩固、家长可选接入 AI”的小学英语学习产品。首发覆盖 P1–P6，以听说读写、词汇、自然拼读和语法的综合发展组织课程。核心学习结果由经过审核的内容和确定性规则产生。

实施已进入M0，且按用户后续要求优先使用Cloudflare免费服务：当前仅Pages/Functions/D1，R2延后；实际执行以 [开发计划](19-development-plan.md) 与 [免费部署手册](20-cloudflare-free-deployment.md) 为准。下表描述完整产品的目标架构。

## 推荐方案

| 层次 | 选择 | 原因 |
| --- | --- | --- |
| 学习端 | React + TypeScript + Vite | 适合可独立缓存的交互应用，避免为学生端引入不必要的服务端渲染复杂度 |
| 3D | Three.js + React Three Fiber + 按需 Drei | React 场景管理；只在地图、角色、少量任务场景加载 |
| 界面 | CSS 语义变量 + 可访问组件原语 + Motion | 活泼视觉、稳定题目布局、统一动效；不同时引入多个动画引擎 |
| 状态 | TanStack Query + 轻量局部状态 | 区分服务端缓存、答题状态和 3D 临时状态 |
| 云端 | Cloudflare Pages + Pages Functions 的 Hono API | 兼容用户的 Pages 部署目标，API 同源 |
| 数据 | D1 + Drizzle；R2 储存自有音频与图片 | 关系型进度和事件适合 SQL；媒体与数据库分开 |
| 身份 | Better Auth 的 D1 适配方案先做技术验证 | 家长身份与儿童档案分离；避免自行实现密码学 |
| 复习 | 首发透明的规则调度，后续可迁移 ts-fsrs | 能解释为什么今天复习；保留事件支持后续重算 |
| AI | 服务端 BYOK 网关 + 协议适配器 | 密钥不进入前端构建；文本、ASR、TTS、实时语音独立配置 |

Cloudflare Pages Functions 可连接 D1、R2 和其他绑定资源，支持这一架构；若后续需要 Durable Objects，须单独部署 Worker 再绑定 Pages。[Cloudflare 绑定文档](https://developers.cloudflare.com/pages/functions/bindings/)

## 完整首发的定义

“小学所有内容”在本方案中落实为：六个年级、十二个学期都有连续课程与阶段检查，主要语言能力均有覆盖。规划 72 个原创主题单元、每单元 4 节微课，共 288 节；每单元至少 36 个独立可判定练习，共 2,592 个；另设约 240 个拼读练习，形成约 2,832 个基础练习。目标建立约 1,440 个词条，去重、词形与分级在编辑审核时确定。这些是生产目标，不是官方词汇量标准。

每个年级首发均具备学、练、复习、阶段评估和家长查看能力。P1–P2 以图片、声音、简短指令为主；P5–P6 保留探险身份，但减少幼儿化装饰。年级不是能力锁，诊断结果可推荐先修补课。

朗文同步是覆盖在自主课程上的映射层。未确定教材系列与版次时，不承诺“与某一册逐课完全同步”；不会把中学 Longman English Elect 的目录当作小学教材目录。

完整首发另包含 [专题特训](17-topic-training.md)，设8类60专题，语法、时态、单词变形与固定句式均有合适入口和交互。固定句式馆覆盖12主题72条表达，训练场景、槽位、固定搭配和合法变体。按错因进行诊断、分层、迁移和延迟复测，复用课程知识点与记忆记录；新增至少480道独立练习后，总基础题生产目标至少3,312道。课程路线负责系统学习，专题路线支持集中补弱。

## 三种实施路线的评估

评分 1–5，为本项目需求下的工程判断，并非实测。权重：Cloudflare 适配 30%、儿童体验 25%、全学段内容建模 20%、可维护性 15%、起步速度 10%。

| 路线 | 适配 | 体验 | 内容 | 维护 | 速度 | 加权 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 以 Tutor and Professor 为主体改造 | 2 | 3 | 3 | 3 | 4 | 2.75 |
| 以 LEGO Grammar 为主体扩展 | 4 | 4 | 2 | 3 | 4 | 3.45 |
| 为本需求新建轻量系统 | 5 | 5 | 5 | 4 | 2 | 4.55 |

推荐第三条。前两条仍需重做多租户隔离、D1 数据层、全学段课程、家长密钥和发布流程，原始代码的节省不一定抵消迁移代价。借鉴拼句子和生成后校验的思路，但不直接拼接三个仓库。仓库现状与旧材料差异见[事实核验](14-references.md)。

## 关键取舍

1. 强动效集中在开始任务、操作积木、完成任务和地图变化。阅读、听音、答题时场景安静，且提供减弱动效和 2D 模式。
2. 所有题目、按钮和进度都具备 DOM 表示。Three.js 为体验增强层，WebGL 失败时照常学习。
3. 无 AI 也有完整基础课程；AI 增强解释、受限情景对话和经过验证的个性化练习。
4. 首发提供轮流按住说话的语音链路；供应商原生实时对话作为后续能力，接入以能力测试为准。
5. 内容生产与软件并行。内部验证可先做代表性课程，但公开首发必须完成 P1–P6 覆盖门槛，不能以两年级的 MVP 代替。
6. 不做排行榜、扣除连续打卡奖励、广告、抽卡付费或开放儿童社交；奖励围绕完成与尝试。

## 投入与立项结论

按 3 名开发、1 名设计、2 名英语教研与兼职 QA 的配置，加入专题特训和固定句式馆后的完整首发估计需要 30–40 个日历周。内容约 2,600 人时，工程约 80–106 人周，详见[估算](11-delivery-plan.md)。单人全职可推进，但应按约 18–27 个月预期并另配教学审核；这不是几周即可完成的全学段产品。

适合立项，前提是将“教材准确映射、儿童可用性、跨家庭隔离、语音供应商兼容性、真实平板性能”作为明确门槛。建议先完成 2 周技术验证和一节端到端代表课，随后并行推进平台与六年级内容生产。此顺序不会改变完整首发范围。
